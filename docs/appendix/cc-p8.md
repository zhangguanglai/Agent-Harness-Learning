## 本册要点

- 上下文窗口是唯一无法靠"更努力"绕开的硬约束：先用 `/context` 看占用，长任务 `/compact` 续做、换题 `/clear` 重开；出现 autocompact thrashing 说明压缩后又被大文件填满，只能靠子代理隔离或新会话。
- 幻觉的判据不是语气而是可证伪性：测试绿 ≠ 行为对（断言弱、mock 过度、只跑 happy path），验收要落在测试、构建、lint、截图与人工看 diff 上。
- 安全靠"默认只读 + 规则 deny + Hook 拦截"三层确定性防线，不靠模型"记得别动 `.env`"；`allow` 授予的是命令模式，不是对模型的长期信任。
- 上下文该分层放置：稳定约定进 `CLAUDE.md`、本次背景进当前提示、海量日志交给子代理、固定校验交给 Hooks、可复用流程做成 Skills，避免根文件膨胀。
- 人的职责收窄为五个变量——目标、上下文、边界、验收、反馈；失败会造成数据/资金/权限/合规风险的决策，判断权必须留在人身上。

## 逐章笔记

### 局限性与应对

- **一句话**：这一章不教怎么用，而是列出代理会系统性失手的几个维度（上下文、幻觉、能力、权限、成本、数据），并用流程、权限与验证把风险压到可接受区间。
- **机制/要点**：
  - 前提设定：Claude Code 是代理循环驱动的高权限本地助手，能读仓库、跑命令、改文件，但它不自带业务先验、不带对工具结果的独立复核、也不理解组织意图——所以人的角色从"写每一行"变成"定目标、设边界、验结果"。
  - 上下文是硬约束而非软性建议：每轮都要重新装入历史消息、`CLAUDE.md`、工具读过的文件与 Bash 输出；接近满载时模型不报错，而是变笨、重复 Read、忘记 `CLAUDE.md` 的禁止项、批准计划后仍偏离。自动压缩反复失败后的"thrashing"是保护机制：压完又被撑满就停手，不白烧 API 额度。
  - 幻觉在这个工具里有一种特殊形态——"测试绿但行为错"：代理能自己调测试工具，弱断言、过度 mock、只覆盖正常路径都会产出虚假的通过信号；此外还有虚构 API/配置项、引用没读过的文件路径。
  - 能力边界是结构性的，不是 bug：原生 GUI 不可点、精确数值与密码学运算不可靠、子代理不能再派子代理（嵌套只有一层）、Agent Teams 多实例成本约 7 倍量级。非交互 `-p` 场景没有人工点权限，必须预置 allow 规则才能跑通。
  - 计费口径要分清：订阅套餐下 `/usage` 的 Session 费用只是本地估算，不等于账单，权威账单在 Console。降本第一杠杆不是省 token 而是缩短上下文与减少轮次，所以"具体提示、分块读取、关无用 MCP、CLI 替代重 MCP"同时降成本与提质。
  - 排障分工：装不上/登录失败、配置不生效、5xx/429/529、IDE 连不上各自对应不同官方文档，先分诊；本地先跑 `/doctor`（会话内）或 `claude doctor`（CLI 起不来时）。
- **命令 / 配置 / 代码**：
```
# 上下文诊断与收束
/context
/compact Focus on the failing test and the last diff
/rename fix-auth-401        # 清窗口前给会话命名
claude --resume             # 事后按名字/列表找回
# 用量与健康检查
/usage                      # 会话 token + 本地估算费用
/doctor                     # 会话内自检
claude doctor               # CLI 起不来时在 shell 里跑
/permissions                # 规则过严 / plan 模式禁 Edit
# 敏感路径硬拦截（原文只给规则串，落盘位置以官方 settings 为准）
Edit(.env)
Edit(**/secrets/**)
Bash(curl *)
# 环境开关
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1
DISABLE_TELEMETRY=1
USE_BUILTIN_RIPGREP=0       # 内置 ripgrep 不可用时改用系统 rg
```

- **坑与边界**：
  - 权限语义的错读：默认只读、写入一般限于启动目录及子目录、被 allowlist 过的 Bash 遇可疑调用仍可能再确认——`allow` 是模式放行，`deny` 才是硬拦截；习惯性通过宽泛 `Bash(*)` 等于把一次误判放大成 `git push`、删库或数据外传，`bypassPermissions` 只配隔离环境。
  - 后台子代理没有交互通道：未预先批准的调用会被自动拒绝，且可能静默失败，事后容易误判成"子代理没干活"。
  - 提示注入没有单一开关：issue、代码注释、被 Read 的文件里都可以写"忽略先前指令"；处理外部 PR 应把代理当"不可信输入的处理程序"。
  - `CLAUDE.md` 不是安全边界：长文档里的条目会被挤掉，关键约束必须落到 Hook 或 `permissions.deny`；第三方 API 路径的数据策略由提供商决定，不等同 Anthropic 商用条款。

- **原文**：https://agent.jeffjade.com/claude-code/limitations/

### 反思与进阶：AI Agent 时代的开发者

- **一句话**：当代理能读仓库、改文件、跑命令之后，开发者要训练的不再是敲代码速度，而是"任务如何被定义、上下文如何被选择、风险如何被约束、输出如何被验证、经验如何被沉淀"。
- **机制/要点**：
  - 角色变化可量化为五个变量：目标、上下文、边界、验收、反馈。每个变量失控都有症状——功能做了但业务路径不对、读了无关文件漏掉真正入口、diff 扩散把重构变成改写、看起来完成却上不了线、同一个错误反复出现。
  - 判断代理产出用"事实 / 逻辑 / 经验"三查：API 与文件真的存在吗（官方文档、本地文件、命令输出）、从问题到方案有没有跳步（计划、调用链、数据流、失败路径）、结论能被什么操作推翻（测试、构建、截图、日志）。反例"前端按钮只有管理员可见所以没有鉴权风险"三项全崩，正确动作是先写一个非管理员 token 调用失败的测试。
  - 需求分解把一句话拆成对象、动作、业务规则、异常路径、验收标准，且**先不写实现方案**。判据：若代理连澄清问题都问不出来，说明上下文不足，补业务规则后再进 Plan Mode。
  - 上下文按生命周期分层：长期稳定约定进 `CLAUDE.md`；本次任务背景进当前提示；大量日志与搜索结果交给子代理（主会话只留结论）；固定校验动作交给 Hooks（到点执行，不依赖模型记忆）；可复用流程做成 Skills（按需加载，避免根文件过长）。
  - 验证分三层并配合审查分离：语法层（能否构建、类型是否通过）、行为层（用户路径：单测/集成/截图对比）、系统层（权限、性能、维护成本、团队约定）。只看语法层是最常见的自欺；同一轮上下文里代理倾向为自己刚写的代码辩护，审查要换会话或交只读子代理。
  - 工作流设计的核心是"把可重复判断外置"：`CLAUDE.md` 管目标与硬约束，Hooks 管格式化/测试/审计/拦截（适合固定动作，不适合语义判断），Skills 管审查模板与迁移流程，SubAgents 管大范围搜索与独立审查，MCP 管外部系统。规则越多冲突越多，少量稳定执行优于堆满。
- **命令 / 配置 / 代码**：
```
# 需求拆解（先不写方案）
把这个需求拆成对象、动作、业务规则、异常路径、验收标准；先指出仍不明确处，不要写方案。
需求：<粘贴需求>

# 目标 / 材料 / 边界 / 验收齐全的一次改动
阅读 @src/content/docs/claude-code/reflection.md 和 @CLAUDE.md。
目标：把文章改成机制清晰、可执行、带失败模式的教程。
边界：不要改其它章节。
验收：运行 pnpm build，检查是否有破折号、省略号、括号说明。

# 三层风险审查（只读）
审查最近改动。按语法层、行为层、系统层列出风险。
每条风险必须给出文件路径、证据和可验证的下一步。不要修改文件。

# 西蒙式渐进实现：拆 3 个最小可交付组块，各给输入/输出/验证命令/回滚方式，批准后再做第一块
# 复盘沉淀：复盘我纠正过你的地方，判断哪些进 CLAUDE.md、哪些做 Hook、哪些只留本次会话
```

- **坑与边界**：
  - 把代理当自动执行器：一句话下发大任务、直接接受大 diff；应先要计划与文件清单（哪些改、哪些不改）。
  - 把 `CLAUDE.md` 写成百科：每次会话都加载大量低频信息，关键约束被稀释，应收窄长度、低频内容改用链接或 Skill。
  - 把 Hooks 写成语义判断机器：在固定流程里塞入不稳定的自然语言判断，结果时灵时不灵；固定动作给命令，语义审查给人或子代理。
  - 决策边界不可让渡：需求取舍、架构边界、安全与权限决策、上线风险判断、团队协作规则五类必须由人主导——原文未给出任何"代理可签字"的例外。

## 跨章节关联

- **与本站前序章节**：
  - 上下文约束的解法在《上下文管理与多代理》（70% 阈值 handoff、`/clear` 冷启动）与《提示工程秘诀》（带验收的提示、Writer/Reviewer 双会话）；本章只给诊断信号，操作剧本在前者。
  - "测试绿但行为错"接《TDD 与质量保障》与《完整实战工作流》（研究 → 审查 → 提交）：验收标准写在哪、由谁执行，两章合起来才闭环。
  - 权限、注入、供应链三条线对应《安全边界与权限心智》与《沙箱隔离机制》：`permissions.deny`、Hooks 二次拦截、dev container/VM 隔离构成纵深；《生态深度集成》补 `allowedMcpServers` 与团队协作配置。
  - 成本与《Token 成本与会话经济学》同源：`/usage` 只是会话级估算，降本落在上下文长度、模型档位（`/model`）、`/effort`、`MAX_THINKING_TOKENS` 与 agent teams 的使用节制。
  - 排障分诊与《调试与错误恢复》《常见问题排查》《CLI 与配置查阅》衔接：本章给"先找对口文档"的表，后者给逐条修复步骤。
  - 反思章四个新能力直接复用《Plan Mode》《CLAUDE.md 编写与维护》《Hooks 机制》《SubAgents》《Skills 技能》；其"流程框架"与《心智模型迁移》同一取向。
- **与通用 Harness 概念的映射**：
  - 代理循环 → "定义目标 → 提供上下文 → 执行改动 → 验证反馈 → 沉淀规则"；循环越清楚代理越像工具，越含混越像噪声放大器。
  - 工具 → 能力边界表：原生 GUI 靠 MCP / Chrome 扩展 / `@browser` 补齐，数值与密码学必须外挂专用库。
  - 权限 → 默认只读 + 规则放行 + `deny` 硬拦截 + Hook 复核，四层而非一层。
  - 上下文 → 最稀缺资源；压缩、分块读取、子代理隔离是同一件事的三种手段。
  - 记忆 → `CLAUDE.md` 与自动记忆属"软约束"，会被挤掉；硬约束必须外置成配置或 Hook。
  - Skill / 子代理 / MCP → 分别是"按需加载的流程"、"隔离上下文的执行单元"、"外部系统接口"，共同点是都不该被当安全边界。
  - 沙箱 → 隔离环境（VM、dev container）是唯一能容忍 `bypassPermissions` 的前提。

## 自测（3 题）

1. 长会话里代理开始重复 Read 已看过的文件，先后该敲哪两个命令？语义差别是什么？
   - 提示：`/context` 确认占用是诊断，`/compact` 保留任务续做、`/clear` 弃上下文重开；若已报 thrashing 则压缩无效，改用子代理跑测试或新会话配更短提示。
2. 代理说"这个接口没有鉴权风险，因为前端按钮只对管理员可见"，事实/逻辑/经验三查怎么拆？第一条动作是什么？
   - 提示：前端可见性 ≠ 后端权限（事实错）、可直接构造请求绕过 UI（逻辑跳步）、用非管理员 token 调接口即可证伪（经验可验）；动作是先写一个应当失败的非管理员鉴权测试。
3. 订阅套餐下 `/usage` 的 Session 费用为何不能当账单？团队控成本应先改哪两处？
   - 提示：Session 费用是本地估算，权威账单在 Console；先收窄上下文（短 `CLAUDE.md` + Skills、分块 Read、关无用 MCP、CLI 替代重 MCP）与轮次（具体提示、Plan Mode 少返工），团队层再设 workspace spend limit 与 TPM/RPM。
