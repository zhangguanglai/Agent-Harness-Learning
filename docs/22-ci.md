# 22 · CI/CD：从本地门禁到镜像发布

> 目标：push 自动跑验证，打 tag 自动出镜像；本地也能一条命令复现。
> 工作流：[ci.yml](../.github/workflows/ci.yml) · [release.yml](../.github/workflows/release.yml) ·
> [dependabot.yml](../.github/dependabot.yml)。

## 1. CI：三个 job

| job | 内容 | 失败通常意味着 |
| --- | --- | --- |
| `labs` | 静态检查（compileall + 链接）+ 16 个实验 + demo + bench | 机制回归或文档断链 |
| `worker` | `node test/worker.test.js` + `spawn.test.js` | 协议/子进程路径坏了 |
| `container` | Buildx（GHA 层缓存）构建 + 无模型冒烟 | 镜像依赖/入口坏了 |

`labs` 与 `worker` 并行；`container` 用 `docker/build-push-action` 的 `type=gha` 缓存，
首次约 5 分钟，之后通常 1–2 分钟。

## 2. 为什么容器 job 不跑真实模型

| 原因 | 说明 |
| --- | --- |
| 成本 | 每次 push 调模型是浪费 |
| 密钥 | PR 不暴露 secret；fork 的 PR 根本拿不到 |
| 可重复 | 模型输出不确定，会让 CI 时红时绿 |

容器 job 只验证**确定性部分**：`dsh --version`、`dsh headless --help`、
容器内 `python -c "import domain.banking_a"`。真实模型冒烟留给手动：

```bash
DEEPSEEK_API_KEY=... python deploy/s0-container/verify.py --build
```

## 3. CD：打 tag 发镜像

```bash
git tag v0.2.0
git push origin v0.2.0
```

`release.yml` 会：

1. 构建镜像并推到 `ghcr.io/<owner>/agent-harness-learning/s0-worker`；
2. 打三个 tag：`0.2.0`、`0.2`、`latest`；
3. 创建 GitHub Release，自动生成变更说明。

镜像名里的仓库段固定为 `agent-harness-learning`（小写）；换仓库名时同步改 workflow。

## 4. 依赖与分支保护

| 项 | 现状 |
| --- | --- |
| Dependabot | GitHub Actions 每周、`spike/dsh-worker` npm 每月 |
| PR 模板 | 变更 / 验收 / 风险三段 |
| 分支保护 | 建议对 `main` 开启：要求 CI 通过 + 1 人 review（需在 GitHub 设置里勾选） |
| 首次贡献者 | 建议开启 “Require approval for first-time contributors” |

## 5. 公开仓库与额度

仓库已改为 **public**：

- 标准 GitHub 托管 runner（`ubuntu-latest`）**免费、不占私有分钟数**；
- 不需要支付方式；此前的「payments failed / spending limit」拦截不再适用；
- 代价：Actions 日志公开、fork 的 PR 默认需要维护者批准才跑。

如果以后改回 private：修账单（Settings → Billing）或改用自托管 runner
（`runs-on: [self-hosted, Windows]`，不消耗额度）。

## 6. 本地等价与 pre-push

> Windows 提示：受限环境里 Node 的管道 spawn 会被拦（EPERM）。跑本地 CI 时不要用
> `python scripts/ci.py | ...` 之类的管道，改成重定向到文件：
> `python scripts/ci.py > ci.log 2>&1`，或直接在终端里运行。

```bash
python scripts/ci.py          # 四个 job 全跑（约 30s，镜像已缓存）
python scripts/ci.py --fast   # 跳过容器（约 20s）
python scripts/check_links.py # 单独查文档断链
git config core.hooksPath scripts/hooks   # 启用 pre-push（跑 --fast）
```

## 7. 覆盖率与盲区

| 覆盖 | 不覆盖 |
| --- | --- |
| 循环/权限/压缩/记忆/技能/子代理/网关/编排/鉴权 | 真实模型行为 |
| worker 协议（loopback + spawn） | DSH 原生 OTel |
| 镜像构建与入口 | 多副本部署、网络策略 |
| DSH bundle 静态与 MCP 工具面 | `--dump-config` 组合（CI 无 DSH 安装） |

`lab12` 在 CI 里会跳过 DSH 组合检查（没有安装环境），只在有 DSH 的机器上跑全量。
