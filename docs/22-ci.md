# 22 · CI：把验证变成门禁

> 目标：每次 push 都自动跑「16 个实验 + bench + worker 测试 + 镜像冒烟」，
> 不再依赖某个人记得在本地执行。
> 工作流：[.github/workflows/ci.yml](../.github/workflows/ci.yml)。

## 1. 三个 job

| job | 跑什么 | 为什么单独拆 |
| --- | --- | --- |
| `labs` | `python labs/verify.py`（16 实验 + demo + bench） | 机制回归，最常失败、反馈最快 |
| `worker` | `node test/worker.test.js` + `test/spawn.test.js` | 协议/子进程路径，和 Python 侧解耦 |
| `container` | `verify.py --build --no-model` | 镜像能构建、入口与 MCP 包可用 |

`labs` 与 `worker` 并行；`container` 最慢（npm 安装 + 构建），单独一条便于定位。

## 2. 为什么容器 job 不带模型 Key

| 原因 | 说明 |
| --- | --- |
| 成本 | 每次 push 调模型是浪费 |
| 密钥 | PR 不暴露 secret；fork 的 PR 根本拿不到 |
| 可重复 | 模型输出不确定，会让 CI 时红时绿 |

容器 job 做的是**无模型冒烟**：`dsh --version`、`dsh headless --help`、
容器内 `python -c "import domain.banking_a"`。这能抓住 90% 的镜像问题
（原生模块、PATH、只读根、tmpfs 权限），且完全确定。

真实模型冒烟（`verify.py --build`，会调一次模型）留给**手动**执行或专门的
定时任务，见 [deploy/s0-container/README.md](../deploy/s0-container/README.md)。

## 3. 本地等价命令

```bash
python labs/verify.py                       # 等价 labs job
(cd spike/dsh-worker && node test/worker.test.js && node test/spawn.test.js)
python deploy/s0-container/verify.py --build --no-model
```

## 4. 覆盖率与盲区

| 覆盖 | 不覆盖 |
| --- | --- |
| 循环/权限/压缩/记忆/技能/子代理/网关/编排/鉴权 | 真实模型的行为 |
| worker 协议（loopback + spawn） | DSH 原生 OTel |
| 镜像构建与入口 | 多副本部署、网络策略 |
| DSH bundle 静态与 MCP 工具面 | `--dump-config` 组合（CI 无 DSH 安装） |

CI 里的 `lab12` 会**跳过** DSH 组合检查（没有安装环境），只在有 DSH 的机器上跑全量。
这是刻意的：不让 CI 依赖一个 1.9 GB 的运行时安装。

## 5. 后续增强

1. **缓存**：Docker BuildKit GHA cache、npm 缓存，把 container job 从 5 分钟压到 2 分钟；
2. **矩阵**：Python 3.11/3.12 × Node 22/24；
3. **手动真实模型冒烟**：`workflow_dispatch` + secret，只在需要时跑；
4. **发布**：打 tag 时构建镜像并推送 registry（需仓库权限）。
